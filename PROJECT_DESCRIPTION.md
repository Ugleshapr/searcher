# Документация проекта: Информационно-поисковая система и конфигуратор оборудования КЭАЗ

Комплексный веб-интерфейс и автоматизированный пайплайн для быстрого поиска, фильтрации, конфигурирования и анализа электротехнической продукции Курского электроаппаратного завода (**КЭАЗ**).

---

## 1. Назначение и концепция проекта

Проект представляет собой клиентское веб-приложение (Single Page Application без тяжелых фреймворков), оптимизированное для сверхбыстрой работы с огромным прайс-листом КЭАЗ (более 200 000 позиций), техническими спецификациями и конфигурацией низковольтного комплектного оборудования.

### Ключевые возможности:
1. **Мгновенный умный поиск по прайс-листу**: поддержка нечеткого поиска, омоглифов, транслитерации, синонимов, разбора номинальных токов и пакетного поиска по списку артикулов.
2. **Интерактивный конфигуратор шкафов OptiBox M**: расчет металлоконструкций и аксессуаров, выбор габаритов, цоколей, внутренних секций, выкатных ячеек OptiMat A с динамической визуализацией (SVG-чертеж фасада и внутреннего конструктива).
3. **Карточки товаров с характеристиками**: детальное отображение технических параметров, документации и сертификатов.
4. **Специализированные режимы работы**:
   - Режим **РЖД** (выделенный прайс-лист для железнодорожного сегмента).
   - Иерархический **Каталог** продукции по категориям с навигацией по хлебным крошкам.
   - Режим **COPY / ОПРЕШ** для быстрого копирования спецификаций в буфер обмена под стандарты проектных и сметных систем.
   - Проверка наличия и сроков поставки через официальный **REST API КЭАЗ**.
   - Определение устаревшей / снятой с производства продукции (**Withdrawn products**) и подбор аналогов / аксессуаров.
5. **Автоматизированный ETL-пайплайн**: регулярная выгрузка, парсинг, нормализация и обогащение данных из официальных источников КЭАЗ (XLS, YML) с помощью Python и GitHub Actions.

## 3. Детальное описание компонентов системы

### 3.1. Поисковый движок и обработка запросов (SearchEngine & Normalizer)
- **Токенизация и лемматизация**:
  - Строка запроса разбивается на смысловые токены (до 18 токенов по 64 символа).
  - Устраняются различия между кириллицей и латиницей через таблицу омоглифов (`с/c`, `а/a`, `р/p`, `о/o` и др.).
  - Разрешаются аббревиатуры устройств защиты (УЗО, ВД, АВДТ и аналогичные сокращения).
- **Пакетный поиск по артикулам**:
  - Если пользователь вводит список из нескольких 6-значных кодов товаров, движок мгновенно переключается в режим выборки точных артикулов.
- **Интеллектуальное ранжирование (RANK_RULES)**:
  - Бонусы позициям с признаком `новый`, аппаратам категорий *Контактор*, *Выключатель*, *Предохранитель*, *Разъединитель*.
  - Поощрение совпадения пар «номинальный ток — отключающая способность» (например, `10А - 100`, `200А - 2000`).
  - Штрафы для устаревших или редких серий (`БЗАВ`, `FERRAZ`, климатических исполнений `ОМ4`, `Т3`).
- **Relaxed-поиск**:
  - Опциональный нестрогий режим: позволяет находить товары даже при отсутствии второстепенных токенов или при числовом сравнении номиналов.

### 3.2. Конфигуратор оболочек OptiBox M (`OptiBoxM/`)
- Предназначен для инженеров-проектировщиков и сборщиков НКУ (низковольтных комплектных устройств).
- **Параметризация шкафа**:
  - Высота: 1600, 1800, 2000, 2200 мм.
  - Ширина: 300, 400, 600, 800, 1000, 1200 мм.
  - Глубина: 400, 500, 600, 800, 1000, 1200 мм.
  - Высота цоколя: 100 или 200 мм.
  - Тип дверей: сплошные, прозрачные (со стеклом), двухстворчатые.
  - Степень защиты оболочки: IP31, IP54, IP55.
- **Внутреннее наполнение**:
  - Сплошные монтажные панели, секционные перегородки, пластроны (фальш-панели).
  - Специфические отсеки для силовых воздушных выключателей серии **OptiMat A** (выкатные корзины, модули зонирования, направляющие).
- **SVG-превью в реальном времени (`preview.js`)**:
  - Переключение видов: **Фасад** (двери, замки, цоколь) и **Внутренний монтаж** (каркас, монтажные стойки, рейки, выключатели).
  - Масштабирование чертежа с сохранением пропорций.
- **Спецификация**:
  - Автоматическое формирование списка номенклатуры (каркас, боковые панели, цоколь, крыша, комплекты объединения, монтажные комплекты).
  - Кнопки копирования перечня в буфер (стандартный формат и формат ОПРЕШ).

### 3.3. Карточка товара (`product/`)
- Автономное представление детальных сведений об оборудовании по URL-параметрам `?art=...&name=...`.
- Парсинг файлов спецификаций (`products_spec.csv` и `products_spec_values.csv`).
- Автоматическая группировка характеристик по категориям (электрические параметры, конструктивные особенности, климатика, стандарты и нормативы).

### 3.4. Дополнительные сервисы и аддоны (`src/addons/`)
- **AvailabilityService**: обращение к API КЭАЗ (`POST availability_calculation_period.json`) с передачей `warehouse_id` и количества, позволяющее мгновенно узнать доступность на складе и ориентировочный срок отгрузки.
- **CopyMode & ОПРЕШ**: переключатель для формирования спецификаций. В режиме ОПРЕШ данные форматируются в структурированную строку: `Наименование / Количество / Оболочка / Артикул` для быстрой вставки в 1С и сметные программы.
- **Withdrawn Products**: фоновая сверка с `keaz-old-products.csv` для оповещения пользователя о снятии товара с производства.
- **FilterPanel & FilterRange**: динамическая фасетная фильтрация по номинальному току, ГОСТ, габаритам и сериям.
- **RZD Search**: переключение источника данных на `rzd.csv` со сменой цветовой гаммы интерфейса на фирменный стиль РЖД.
- **Catalog Addon**: древовидная навигация по каталожным группам на базе `camerged.csv`.

## 4. Пайплайн данных и автоматизация (`automation/`)

Скрипт `make_base_auto.py` отвечает за автоматическую актуализацию номенклатурной базы:
1. Загружает прайс-лист в формате XLS с официального FTP/сервера КЭАЗ (`https://files.keaz.ru/ftp/keaz.xls`).
2. Загружает товарный каталог в формате YML (`https://files.keaz.ru/uploads/products-electro-msk.yml`).
3. Нормализует колонки (артикул, наименование, цена с НДС).
4. Очищает названия от лишних артефактов и экранирования.
5. Связывает позиции с прямыми ссылками на техническую документацию, паспорта и 3D-модели.
6. Экспортирует оптимизированный файл `base.csv` с разделителем `;`.

Запуск выполняется автоматически через **GitHub Actions** (`build-base.yml`) каждый день в 05:00 UTC (08:00 МСК). При обнаружении изменений обновленный файл коммитится ботом в репозиторий и запускается пересборка страниц.

## 6. Запуск и локальная разработка

Так как приложение состоит из статических файлов и ES6-модулей, для локального запуска требуется любой локальный HTTP-сервер (из-за ограничений CORS при работе с `fetch` и ES-модулями по протоколу `file://`).

### Вариант 1: С помощью Python
```bash
# В корне проекта:
python3 -m http.server 8000
```
После запуска открыть в браузере: `http://localhost:8000/`

### Вариант 2: С помощью Node.js (npx serve / live-server)
```bash
npx serve .
# или
npx live-server
```

### Запуск ETL-скрипта генерации базы:
```bash
cd automation
pip install -r requirements.txt
python make_base_auto.py
```
Итоговый файл `base.csv` появится в корне репозитория.
